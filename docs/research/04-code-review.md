## What was tried and found clean

- **Sanitizers.** The full ctest suite (teststrategy, testcomposer, testbami, testbridge, testsessioninit) passes under ASan+UBSan, with leak detection on. Valgrind is clean on testcomposer and testbami (testbridge: Go-runtime noise, inconclusive). TSan cannot run in the container (`personality()` is blocked),.
- **Per-IC property lifetime.** I suspected the property factory outlives `Composer`. Destroying a Composer and then creating an IC runs clean under ASan, because Fcitx's `FactoryFor` unregisters itself. Deferred lambdas hold `ic->watch()`, so a destroyed IC is skipped. `dispatcher_` is destroyed after `composer_`.
- **Go engine fuzz** (`$S/fz/fz_test.go`, 2 x 60 s, about 140k execs, mixed corpus, all 9 variants, random options). Invariants: Apply(screen, Edit) == Preedit; DeleteN within the screen; preedit valid UTF-8 and NFC (x/text); preedit length <= keys; Commit resets; not-consumed means an empty Edit. No violation.
- **Bridge fuzz** (`$S/w2/bridge/fz_test.go`, 60 s, about 160k execs). Random live, freed, zero, -1 and bogus handles; double `BamiFree`; `Configure` with out-of-range values; arbitrary 32-bit runes including surrogates and values above 0x10FFFF; `AckShown` with arbitrary text. Every stale handle gave -1/NULL with nil outputs. There was no panic, and the deleteN and NFC invariants held. cgo handles are monotonic and never reused, so a stale handle cannot alias a new IC. Each exported function has a recover; the two key paths reset the engine on a panic.
- **Property state machine for the composer** (`$S/w/test/proptest.cpp`). An edit-mode composer and a PreeditOnly composer get the same random sequence of keys (including emoji, combining marks, `é`), Backspace, Return, arrows and Shift+Backspace. The sequences ran on dbus, ibus, wayland, wayland_v2 and xim, with ProtectEnglish and ClientPreedit toggled. Visible text (app text plus preedit) must match after every step. With synchronous updates, 1500 seeds x 60 steps gave 0 divergences under ASan+UBSan. With dropped or late updates it diverges only by the finding 2 pattern (the word falls back and is not composed). Text is never duplicated or lost in the cases seen.
- **Offsets.** `diffText` counts code points and backs up to a lead byte. `expected = cur - deleteN + len(insert)` cannot underflow, because `endsWith(before, shown)` forces `cursor >= len(shown) >= deleteN`. A selection (anchor != cursor) goes to preedit without sticky. An NFD app text mid-word gives TextMismatch + sticky (safe). Text ending in ZWJ or a combining mark gives NotBoundary (safe).
- **R1-R9.** The numbered list is not in the repo: `docs/PLAN.md` names R1-R9 but the PRD body is empty. I checked the PLAN "Strategy-rule changes" bullets instead: freshness, flag-is-not-enough, Wayland rejected delete, bounce without a timer, terminal and selection, one delete first. All are reachable only into preedit, never into a destructive edit, except through finding 4's 3-byte gap and finding 2's visible mis-composition.
- **cgo and signals.** All C strings come from `C.CString` and are freed with `C.free` through `BamiFreeString`. On every rc>=0 path the caller frees. The Go runtime added no sigaction changes beyond finding 5.
